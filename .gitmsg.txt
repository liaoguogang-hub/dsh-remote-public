fix(plugin): connect.cmd 打开的二维码页可能是死链（0.3.2）

现象：双击 connect.cmd / dsh-remote start --open 后浏览器打开 http://127.0.0.1:2839/... 打不开。

根因：
- status.json 是上次运行（或测试）留下的陈旧文件，写着旧端口 2839
- 桥接已在 6300 运行，走"采纳已有桥接"分支时直接返回了 readStatus()，于是 CLI 用陈旧端口拼 URL

修复：
- 采纳分支改为以 /_dsh-remote/health 的实时数据重建 status（端口/authority/上游），并写回
- openPairPage / qr 命令在打开前都先探 health，自动在 [status 端口, 6300] 里找活着的桥接
- 没有活桥接时不再打开死链，而是提示先运行 dsh-remote start / 双击 connect.cmd

验证：
- status 被人为改成 2839 → start 采纳 6300 并纠正 status，打印正确配对页
- 无桥接时 qr 输出"桥接还没运行"
- 正常 start --open：监听 6300、打印配对页、/pair 返回 200
